# aigent acts: an agent over three annual reports, graded on how it got there

*Milestone `v0.2-agent`. Draft of 2026-09-28; the GPU section lands with Week 5.*

`v0.1-rag` answered questions over the FY25 annual reports of ITC, Reliance and Tata Motors by
retrieving once and answering. Here the model gets retrieval as a tool beside a calculator, the
clock, a file reader and web search, and decides for itself what to call. The question is not only
*was the answer right*, but *did it get there the right way*.

## The task set

25 hand-written tasks, each needing more than one step, in six families: search then calculate
(11), compare two reports (3), a report figure converted at today's exchange rate (3), a sandbox
file plus a report (3), a report plus the date (2), and three that must be declined because the
premise is false or the answer is not in the reports. Each task names the tools it requires, the
tools it forbids, the order any two must come in, and a reference answer.

Four graders score every run. Three are free and read the trajectory: the right tools were called,
in a sane order, and the run finished with an answer. The fourth is an LLM judge, always a
different model from the agent, grading the answer against the reference. A task passes only if all
four do.

## The numbers

| Build | Agent | Passed | Cost a task | Input read from cache | Saved by caching |
|---|---|---|---|---|---|
| **LangGraph, final** | **Opus 5** | **19/25** | **$0.116** | **55%** | **31%** |
| LangGraph | Sonnet 5 | 23/25 | $0.038 | 58% | 35% |
| Google ADK | Sonnet 5 | 20/25 | $0.037 | 56% | 33% |
| SDK tool runner | Sonnet 5 | 16/25 | $0.039 | 54% | 30% |
| LangGraph | Opus 5 | 20/25 | $0.101 | 53% | 28% |

The final row runs on the current prompt and judge; the others came earlier, before the last
fixes to both. No model judges itself. Cost a task includes the judge; the caching columns
price the agent's calls against the same tokens uncached. A task averaged 2.9 turns. Every call
passed one gate that counts tokens for free and refuses anything above a per-turn ($0.60) or
per-task ($0.50) ceiling before sending, so all of Project 2, about $11, was bounded before it was
spent.

**Known limitation.** The last-answer turn keeps web search on offer, so the cache still matches,
and is priced as if it could search again. At Opus prices no last answer then fits under $0.50, so
pt-015 ends empty-handed on Opus, both runs.

**Read the scores as a range, not a ranking.** Each row is one run. The same LangGraph agent scored
15 and then 23 on consecutive runs, and four of the tasks that flipped had nothing changed between
them. The spread of one build covers the gap between all three.

## What failed, and whose fault it was

The first full run passed 16 of 25. Of the nine misses, **six were ours, not the agent's**: a
LangGraph bug that echoed a `null` field back to the API and got a 400 on four web tasks, and a
judge whose 256-token verdict cap was eaten by its own reasoning. The next run found four more:
labels built from exchange rates their author had guessed, a figure the reports state two ways,
and a judge that called the agent's correct, current exchange rate "implausible" because it
remembered an older one. Building an eval is mostly finding out that the eval is wrong.

The judge needed three fixes before it could be trusted on web answers. It is told today's date,
since without it the date a web answer states reads as invented. The rubric forbids judging a web
figure against the judge's memory. And it is shown the pages the answer cited: the API's structured
citations sit beside the answer's text, not in it, so the judge had been failing cited answers as
unsourced. That last fix exposed a model difference. Opus attaches structured citations to its web
answers; Sonnet 5, on every run so far, attaches none.

**The agent's own misses are instruction-following, not reasoning.** Across every build and both
models, the recurring failures are the same few: easy arithmetic done in the head where the prompt
asks for the calculator, today's date assumed rather than read from the clock, the web searched for
a figure the reports hold, and web figures credited to "recent market data". The stronger model
followed instructions *less*: in both its runs Opus answered three calculator tasks correctly
without it, at about three times Sonnet's cost. Two sentences in the system prompt, asking
for the site and date beside every web figure, turned unsourced web answers into sourced ones.

## One agent, three frameworks

The same prompt, tools and graders were built three times: on the Anthropic SDK's tool runner, as a
LangGraph graph, and on Google's ADK. CrewAI, the fourth, pins dependencies too old to install here.

The frameworks moved neither the score nor the bill, because everything that decides either
(admission, ceilings, the last answer when out of room, caching, the ledger) was already ours and
had to be routed through each framework, not replaced by it. The difference is who owns the
conversation. LangGraph leaves the message list in our hands. ADK translates history every turn,
dropping server-side web search and rewriting thinking, and each loss surfaced only as a 400 from a
live run after every offline test had passed. For this agent the answer is our own loop.
LangGraph earns its place when the work needs checkpoints, human approval mid-run or several agents
sharing state. Full memo: `docs/agent-frameworks.md`.

## A toy fine-tune, graded by Project 1a's eval

Week 4's other track wrote LoRA and the DPO loss from scratch in `underhood`, then checked the LoRA
layer against peft's and mlx-lm's. It computes the same update, but kept its adapter in the base
weights' dtype where both libraries keep float32, which on a bf16 model rounds small updates away;
that is fixed. The toy fine-tune puts the idea to work on Project 1a's task: Qwen3-1.7B at 4-bit,
trained on 180 headlines built from templates, so every label is exact and none shares four words
with a real one, then graded on the 50 hand-labelled headlines by the harness that graded Opus
(48 or 49 of 50). Rank 8, scale 2, 200 steps of batch 4, loss on the answer only, all local and
free.

| Qwen3-1.7B 4-bit | Trainable | Whole record, zero-shot | Few-shot |
|---|---|---|---|
| base | — | 11/50 | 16/50 |
| 7 projections, last 16 blocks, no dropout | 5.0M | **41/50** | 27/50 |
| q and v, all 28 blocks, dropout 0.05 | 1.6M | 37/50 | 25/50 |
| 7 projections, all 28 blocks, dropout 0.05 | 8.7M | 40/50 | **34/50** |

**Templates alone took the model from 11 to 41.** What they taught carried over to real headlines:
a missing percentage read as null rose from 1 to 12 of 16, and decoy numbers from 0 to 7 of 10.
What they never showed did not: subsidiaries and narrowed metrics stayed at zero.

**A third of the parameters kept most of the gain.** Adapting only the attention's q and v
projections kept 26 of the 30 extra records. The first two tuned rows differ in three things at
once: which projections, how many blocks, and dropout. The third row changes one at a time: against
the second it adds the MLP projections, and against the first it adds all 28 blocks and dropout.
The MLP projections bought back three of the four records (37 to 40), consistent with the MLP
holding more of what a model knows; the blocks and dropout moved zero-shot by one, which is noise.
Each row is one training run, so the one-record gaps are a direction, not a measurement.

**Tuning and prompting do not add up.** Every adapter does worse on the few-shot prompt than on the
zero-shot one it was trained with, since a second prompt is off its training distribution; the base
model is the other way round. How much worse is where the settings showed: 14 records lost for the
first adapter and 12 for the second, but only 6 for the third, which is the only one with both the
MLP projections and dropout. Zero-shot barely separates the adapters; an unfamiliar prompt does. And
validation loss says little here: its 20 rows come from the same templates as the training rows, so
it bottomed at 0.003 while the real test still missed 13 records. One caveat belongs beside every
number: the templates' author had read the test set. The four-word guard stops copying, not knowing.

## Reproduce

```bash
uv run --group graph python -m aigent.agent_tasks --model claude-opus-5 --judge-model claude-sonnet-5
uv run --group graph python -m aigent.agent_tasks --model claude-opus-5 --judge-model claude-sonnet-5 \
  --cache --yes --limit 12.80    # the final run; the dry run above prints its worst case
```
