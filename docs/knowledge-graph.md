# aigent knowledge graph

A map of what exists in this repo, what it does, and how the pieces point at each other. Written for
a future session that needs orientation before touching code.

**Verified against commit `b8c6698` plus the fine-tune's training corpus, landing in this commit
(2026-10-10). 1261 tests pass; pyright and ruff are clean.**

> **The package is organised by capability, not by week.** `week01/` became `extraction/`
> (Project 1a) and `week02/` became `retrieval/`; the test tree mirrors it. Roadmap weeks still
> appear in §5, where they are dates rather than module names.
>
> **Snap and roll, twice a week, both repos as one** (2026-10-07; one joint run since 2026-10-08):
> aigent's `release.yml`, Mon and Thu 00:07 IST. `snap` branches underhood's `main` and then
> aigent's, re-pinned to it on the snap branch only, as `snap-YYYY-MM-DD` (the last eight kept in each); `roll-underhood` and
> `roll-aigent` run each repo's checks on its snap; `stable`, only if both pass, tags both snaps
> `roll-YYYY-MM-DD`, the day they rolled, and moves both `stable` tags. All or nothing. underhood
> has no release workflow of its own. Nothing reaches `main` but a merged PR (both repos'
> rulesets, 2026-10-09).
>
> **underhood is a dependency** (2026-10-07), for its GPU pricing: a git source. **The mains pair, and
> the snaps pair** (2026-10-08): `main` pins underhood `branch = "main"`, locked by `uv.lock` to the
> last underhood commit the mains CI passed with; a snap branch pins underhood's snap of the same
> date. underhood declares no dependencies, its model stack being in dependency groups only its
> own `uv sync` installs, so aigent gets `config` and `gpu/` and never torch through it. It is the
> seam for starting a GPU session for a local model from aigent.
>
> **Everything that talks to a model lives in `llm/`** (2026-10-07): `core` (the door, which was
> `llm.py`), `messages`, `pricing` and `adapters/`, moved whole with history. `llm/__init__.py`
> imports nothing, since `config` imports `adapters` while `core` imports `config`; callers import
> from the submodules. `config`, `errors` and `tracing` stay top-level.
>
> **The demo code is gone** (2026-10-07): Week 1's five `primitives/` and the `aigent` command
> that ran them, and `workflows.demo`, the per-question command line the patterns and agents
> shared, with every `main`/`show` that ran through it. The patterns and agents remain as tested
> functions; agents run through `agent_tasks`. Their recorded results stay in `LOG.md`.

> **Week 3 opened with the five workflow patterns** from "Building effective agents", in
> `workflows/`: chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer,
> each under 100 lines, each over the Project 1 corpus, every call through `llm`. Written and
> tested for free against the fake client, then run live for about $0.55 (2026-09-22). Three of
> five answers were honest declines on retrieval misses: search, not the models, is the bottleneck.

> **The first agent runs on the SDK's tool runner** (`agent`, through `llm.core.run_tools`). The runner
> keeps the echo, one-message and error-result rules, but by default it has no turn cap, no
> pre-flight and no budget, and running out of turns looks like finishing. `run_tools` counts and
> admits every turn before it is sent, and raises at the cap. Read against the source in
> `docs/tool-runner.md`.

> **Retrieval runs end to end**: chunk → embed → rank → grade → report. Written by hand against
> tests that were written first, the same arrangement as the `underhood` repo (Track B).
>
> **The corpus is real and ingested.** Three Indian annual reports — 1,148 pages, 4.2M characters
> raw — load through `retrieval.corpus` into three `Document`s of 4,040,587 characters. The 3.8%
> that ingestion removes is running headers and page numbers. The question set is 54 questions
> labelled with verified quotes, 19/16/19 across the three reports.
>
> **The result that outranks every number below it (2026-09-20).** The same six retrieval arms were
> run over two question sets that differ *only* in wording — same corpus, same chunks, same 54
> quotes, same labels — and they recommend **opposite systems**. On questions authored from the
> passages, `bm25+rerank` wins at hit@5 0.907 and fusion is worse than BM25 alone. On paraphrased
> questions, BM25 falls from best to worst (0.889 → 0.315, below dense), and fusion becomes the best
> base. **An eval whose questions were written while looking at the passages will recommend the
> wrong retriever.** Treat any single retrieval table here as conditional on its question style.
>
> **Both halves are measured.** Generation, 2026-09-19, all 54 cases for $1.342: closed-book
> `correct` 5/54 against RAG's 42/54, and closed-book **answered 10 and was right 5** where RAG was
> right 42 of 43 answered. Retrieval, `retrieval.evaluate`, 2026-09-18, three strategies, $0.00: hit@5 **0.635 / 0.630 / 0.685**, recall@5 0.619 / 0.583 / 0.608, MRR 0.471 / 0.511 / 0.452
> for `fixed` / `fixed+overlap` / `by_sentence`. **Three metrics, three different winners**, and
> the spread is inside what 54 questions can resolve — a four-case gap on 54 paired rows cannot
> reach p<0.05 by a sign test even if every discordant row falls the same way. The honest reading
> is that these three strategies are not distinguishable on this dataset, which is a finding about
> the dataset's size as much as about the chunkers. Quote the number with the metric and the
> strategy, or do not quote it.

If the code has moved since, trust the code and update this file (see [Maintenance](#maintenance)).

- Package root: `src/aigent/` (uv build backend, `src` layout, Python 3.12+)
- Entry points: `python -m aigent.<pkg>.<mod>` for the paid runs; no console script
- Everything paid goes through two modules: `config.py` builds the client, `llm/pricing.py` prices the
  call and guards the spend. Nothing else does either.

Reading order for a newcomer: `config.py` → `llm/pricing.py` → `tools.py` → `llm/core.py`. The rest are
variations on a call through it. For the harness, read `evals/grade.py` first — the vocabulary explains
the runner, not the other way round.

Note which way the arrows do *not* run: `evals` imports no capability module. The harness measures whatever it is handed.

## 2. Nodes

Stable IDs are `module.Symbol`. Cite them in future notes; they survive line drift.

### 2.1 Modules

| ID | Path | Role |
|----|------|------|
| `config` | `src/aigent/config.py` | **Every tunable constant except the tool pair's and each client's**: credentials, model selection, spending ceilings, output caps, loop caps. The only module that constructs a client. Holds no arithmetic. |
| `llm.pricing` | `src/aigent/llm/pricing.py` | Token prices, cost arithmetic, and the two budget guards that enforce `config`'s ceilings. The only module that knows a price — **including a local model's** (2026-09-23), priced at what an hour of this machine costs over the tokens an hour buys, so a local run reads as cheap rather than as free and every guard keeps working. **Since 2026-09-29 that hour is its electricity alone** (~25 W at ₹8/kWh, $0.0021): the machine is owned either way, and amortising it had priced a local 4B above Sarvam's hosted 105B. Since 2026-09-23 it prices a `llm.messages.Usage` and imports no provider SDK. |
| `llm` | `src/aigent/llm/` | The package for everything that talks to a model (2026-10-07). Its `__init__` imports nothing, by necessity: `config` imports `llm.adapters`, and `llm.core` imports `config`, so a re-export there would be a circular import. |
| `llm.messages` | `src/aigent/llm/messages.py` | **The neutral types** (2026-09-23): `Msg`, `Block`, `Tool`, `Cache`, `Thinking`, `OutputConfig`, `Usage`, `Reply`, `Parsed`. What a request carries and a reply returns, in this repo's own types, so no caller names a provider's. The shapes mirror Anthropic's, the richer of the two wires; the OpenAI adapter flattens what it can and refuses what it cannot. Imports only pydantic, so anything may import it. |
| `llm.adapters` | `src/aigent/llm/adapters/` | **The clients we can talk to, and the wire each speaks** (2026-09-23) — the only place an SDK is imported. A *client* is a named endpoint (`anthropic` today, a local `mlx_lm.server` next); an *adapter* is the class that speaks its wire. `CLIENTS` maps a client name to its settings (from its own `cfg_<name>.py`), `WIRES` maps a wire name to the class that speaks it, and `build(client, sdk)` makes an adapter over a vendor client if handed one, raising on an unknown name rather than defaulting — guessing would send a request somewhere nobody asked for. **Many clients may share one adapter** (anything OpenAI-compatible speaks one wire) but a client maps to exactly one, so the name is enough to pick it. `Adapter` is the protocol `llm` calls — `count`, `send`, `parse`, `streamed`, `tools` — with `Streamed` and `ToolSession` for the two that return something to drive. `llm.adapters.anthropic.Anthropic` holds one SDK client, built on first use so an import needs no credentials, and converts both ways (`usage_of`, `reply_of`). **`reply_of` drops unset fields** (2026-09-28): the API returns `server_tool_use.caller: null` and refuses it when the block is echoed back, which broke every web-searching task in Project 2's first full run. Its `ToolSession` is the wire half of a tool-using conversation — iterate turns, run the tools, send a last answer with the same tools so the cache still holds — while `llm` admits and bills each turn. `Streaming` exposes neutral text and a final `Reply`, plus `raw` for the one demo that is about Anthropic's own events. Two wires so far: `anthropic`, and `openai` (2026-09-23) for anything serving `/v1/chat/completions` — the local `mlx_lm.server`, vLLM later, OpenAI itself. The OpenAI wire counts through the served model's own tokenizer, and **asks it for `return_dict=False`**: transformers v5 otherwise answers with a `BatchEncoding`, whose length is its field count, so every prompt counted 2 and passed every ceiling until a live call showed it. Six clients (2026-09-23): `anthropic`, and five served by one local `mlx_lm.server` — `local` (Qwen3-4B at 4-bit), `local-4b-6bit`, `local-4b-8bit`, `local-4b-bf16` and `local-8b-4bit`. They are one file, `cfg_local.py`, because they differ only in which weights answer. **Two more for the toy fine-tune** (2026-09-28): `local-1.7b` (Qwen3-1.7B at 4-bit) and `local-1.7b-toy`, the same weights with underhood's adapter; since 2026-09-29 one client per projection set, reading `TOY_DIR / "adapter-<set>"`: `local-1.7b-toy` (q and v) and `local-1.7b-toy-all` (all seven). A client's `adapter` rides in the request body as `adapters`, which `mlx_lm.server` 0.31.3 reads per request, so one server answers as both — swapping weights between them, so each client's rows run together. **A record is asked for by naming its keys, never by sending a JSON Schema** (2026-09-24): a model handed a schema answers *with* the schema — Qwen3-8B parsed 0 of 12 replies that way against 12 of 12 when the fields were described, and the echo cost 27 of 54 rows in a judged run. `record_in` still unwraps an echoed schema's `properties` rather than discarding a right answer in a wrong envelope. **Timeout and connection reuse are the client's** (`timeout`, `keepalive_seconds`): the SDKs default to a 600-second read and minutes of keepalive, which let one dead socket stall an eval for three hours on 2026-09-24 with the process idle on an established connection carrying no traffic. A hosted API gets 180s, a local server 1800s because it may be loading or downloading weights inside the first request, and both drop idle connections after 30s. **A client's `template_kwargs` ride with every request and into its token count**, which is how `enable_thinking: False` reaches Qwen3's hybrid models: thought is billed against the output cap, so a record would never be reached. Every local client carries it, including those whose own model ignores it, because the judge is reached through the *task's* client. A Qwen2.5-7B was served here until 2026-09-23 and was dropped: it lost 16 of 54 rows writing prose where a JSON object was asked for, and it had been the judge — the job that failure makes it worst at. **The server keeps one model resident** and swaps on request, so a comparison runs a client's prompts together and throws away the first call, which pays for the load. A new client is a `cfg_<name>.py` and a row in `CLIENTS`; a new *wire* is a class and a row in `WIRES`. `llm.adapters.client.Client` is the shape of those settings: name, wire, three models, an optional `base_url`, and `max_tokens` overrides by call-site key. **A hosted OpenAI-compatible client** (2026-09-29): `sarvam`, in `cfg_sarvam.py`, serves `sarvam-105b` from `api.sarvam.ai`, and is graded by Sonnet 5 on the `anthropic` client: **a client's `judge_client` names the client that grades it** (`llm.adapters.judge_of(client)`, else the client itself; `sarvam` names `anthropic`). `Llm` stays one client and knows nothing of judging: code that grades builds its own `Llm` on the judge's client, whose cfg supplies the judge model, its caps and its adapter. `retrieval.answer` defaults `--judge-client` to `judge_of(--client)`; `LlmJudge.client` is the client the judge runs on. `Client` gained `api_key_env` (the variable holding its key; the wire raises if it is unset, and a local server still gets a placeholder), `tokenizer` (the Hugging Face repo that counts for a served id that is not one, always loaded with `trust_remote_code=False`), `constrains_schema` (the server enforces a record's JSON Schema, sent as `response_format`; `sarvam` only, since Sarvam prompted alone answered in prose or tags, 2026-09-29), and `extra_body` (provider fields such as `reasoning_effort`, which `sarvam` sends as null: reasoning is billed as output, and `low` spent a whole 2048-token cap on it). The cap is sent as `max_tokens`, which Sarvam documents and `mlx_lm.server` also reads. **Credentials moved here too** (2026-09-23): `llm.adapters.anthropic.get_client` / `has_credentials` were `config`'s, and building a client is the wire's business — which is also what lets `config` read the active client's settings without a cycle. |
| `llm.adapters.retry` | `src/aigent/llm/adapters/retry.py` | **The one retry layer** (2026-10-06). `RetryingTransport` wraps each wire's HTTP transport, so every request either SDK sends is covered: plain calls, parses, counts, streams and each turn of the SDK's tool runner, which `llm` cannot reach. Both SDK clients are built with `max_retries=0`; the Anthropic SDK had silently retried twice, timeouts included. **Retried:** 429, 500, 502, 503, 504, 529, and a connection refused or never made. **Never:** a timeout or a dropped response, since the server may have finished and billed it, and the budget sees one bill per call. `x-should-retry` from the server overrides the status. **Wait:** the server's `retry-after` (seconds or HTTP date) if it sent one, giving up if it asks for more than the cap; otherwise full jitter, a uniform draw under `base * 2**(attempt-1)` and the cap. Each retry is logged on `aigent.retry`. `http_client(...)` builds the httpx client both wires use. Settings are the client's: `Client.retries` 3, `retry_base_seconds` 1.0, `retry_max_seconds` 30.0. |
| `llm.core` | `src/aigent/llm/core.py` | **The one door to a model** (2026-09-21): every request is counted, admitted against a budget, sent, billed and traced. Every call shape the repo uses — plain, structured, streamed, tool-using, concurrent — has a method here, and every call in the package goes through it. **It imports no SDK** (2026-09-23): the wire lives in `adapters`, including the tool runner and streaming, so what remains here is policy — counting, ceilings, holds, billing, the trace, concurrency. A caller never names an adapter: `Llm(client)` takes a **client name**, defaulting to `config.CLIENT`, and builds the adapter behind `_adapter`. `Llm.client` gives that name back and `Llm.sdk` hands the vendor client on, so an eval and its graders share one connection — the eval seams (`answer_task`, `extraction_task`, `graders`, `LlmJudge`) thread both. A test fails on any module but an adapter calling `client.messages` itself (invariant 8). **It also refuses what a wire cannot do** (2026-09-23): `_asks_for` reads the capabilities a request needs — cache, thinking, effort, tools, web_search — against the adapter's `supports`, and raises `Unsupported` before counting or sending. A wire that silently dropped a cache marker or a schema would answer anyway, differently and for a different price, which is the one failure a budget guard cannot catch. |
| `guardrails` | `src/aigent/guardrails.py` | **Three guards around Project 2's agent** (2026-10-06). **In:** `check_task` trims a task and raises `errors.GuardrailTripped` on one that is empty, over `config.MAX_TASK_CHARS`, carries control characters or contains a credential, before anything is counted or sent. `redact(value)` replaces every credential-shaped string with `[redacted credential]` through any nesting of dicts and lists; `tracing.masked` hands it to Langfuse as the client's `mask`, so no observation's input, output or metadata leaves with a key in it. **Through:** the fence itself is `tools.fence`, applied by `tools.execute_tool` to `tools.UNTRUSTED_TOOLS` (`read_file`), so every caller of the dispatcher gets it: all three agent builds and the MCP server. `UNTRUSTED_NOTE`, appended to `agent.SYSTEM`, tells the model fenced text and web pages are data, never instructions. Web search results arrive server-side and cannot be fenced; the note covers them. **Out:** `check_answer(text, found)` validates a Pydantic `Answer` with one field per rule, so every broken rule reports: the text is non-empty and under `config.MAX_ANSWER_CHARS`, every `DOC#nnnn` it cites **inside square brackets** (`cited`) was retrieved in this run, an id merely mentioned not counting, and nothing in it is shaped like a credential (Anthropic, Langfuse and OpenAI keys, AWS key ids, private-key headers). `shown` withholds an answer only for a credential; the rest is flagged. **The note changed `agent.SYSTEM`**, so runs after 2026-10-06 are not prompt-identical with the 19/25 headline. |
| `errors` | `src/aigent/errors.py` | **Every error the package defines** (2026-09-22): `BudgetExceeded`, `DatasetError`, `StepFailed`, `TurnsExhausted`, and `GuardrailTripped` (2026-10-06). Imports nothing, so any module can raise one without an import cycle. Reuse one before adding another (invariant 23). |
| `tracing` | `src/aigent/tracing.py` | **Every eval row, model call, tool call and grade as one nested tree in Langfuse** (2026-10-06). The only module that imports the Langfuse SDK (v4, OpenTelemetry underneath). `Tracer` is the protocol (`observe(name, kind, inputs=, metadata=, tags=, session=)` → an `Observation` with `finish`, `bill`, `score`); `LangfuseTracer` speaks it, `Silent` is the no-op, and `tracer()` picks one on first use: Langfuse only when both `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are set and `config.TRACING` is not `off`. `traced_tools(dispatch, kinds)` records each tool call as a `tool` observation, or the kind `kinds` names. **Cost on a generation is `pricing`'s figure, sent as `cost_details`**, not Langfuse's own table, so web searches and local models are priced as everywhere else. Follows Langfuse's best practices (fetched 2026-10-06): names are fixed operations with the detail in metadata, each node has its most specific type, grades are trace scores rather than tags. |
| `tools` | `src/aigent/tools.py` | Framework-free tool implementations + their JSON schemas + a name→function dispatcher. Imports nothing from this package except `tools_config`. **The dispatcher fences** (2026-10-06): `execute_tool` returns a `read_file` result inside `fence`'s `<untrusted>` element, so no caller can forget to (invariant 28). **And it gates writes** (2026-10-08): a `WRITE_TOOLS` name (`write_file`) runs only for a caller passing `writes=True`, which only `mcp_server` does, because the agents dispatch whatever name the model sends (invariant 29). `sandbox=` reaches both file tools, so a caller can point them elsewhere. |
| `report_tools` | `src/aigent/report_tools.py` | **Tools over the annual reports** (2026-09-22): `search_reports`'s schema, what runs it, and the record of each search. The home for any tool that needs the rest of the package, which is exactly what `tools` must not import. Moved out of `agent` so the agent holds only its choice of tools and its loop. |
| `mcp_server` | `src/aigent/mcp_server.py` | **The reports' search and the sandbox's files as an MCP server** (2026-10-07; files 2026-10-08), on the `mcp` SDK 2.x (`MCPServer`, which was `FastMCP` in 1.x), over stdio: `uv run python -m aigent.mcp_server`. **Three tools.** `search_reports` is the one capability no client has; `read_file` and `write_file` were added on 2026-10-08 at Vedant's request, though a client like Claude Code has its own, so the server is a complete toolbox over aigent's sandbox. `calculate` and `current_time` stay out. `build_server(search, sandbox=SANDBOX)` registers `search_reports` over `report_tools.ReportSearch` with `SEARCH_TOOL`'s description, `report` defaulting to `all`, its query through `guardrails.check_task`; the two file tools go through `tools.execute_tool(..., sandbox=, writes=True)` with `READ_FILE_TOOL`'s and `WRITE_FILE_TOOL`'s descriptions, so a read arrives **fenced** and a write is **create-only**, and carry MCP annotations (`read_only_hint` true for the read, false for the write, `destructive_hint` false). Every refusal is raised as the SDK's `ToolError`, **the only exception whose text reaches the client**, with the dispatcher's `Error: ` stripped since the SDK prefixes its own. `LazySearch` builds the real search on the first call, under a lock and once, so the server starts before the models load (first search ~19 s). The SDK claims fd 1 for the protocol and diverts stray stdout to stderr, so search setup's prints cannot corrupt it. |
| `tools_config` | `src/aigent/tools_config.py` | The constants `tools` needs, in a config module that travels with it. Imports nothing internal at all. |
| `extraction.synthetic` | `src/aigent/extraction/synthetic.py` | **The toy fine-tune's training set** (2026-09-28): 200 headlines built from sixteen templates, each applying one rule the field descriptions state, so every label is exact by construction. Rendered through the local wire as `extraction_task` would send them, and written as `mlx_lm` chat rows for underhood to train on. Free and offline. |
| `extraction.baseline` | `src/aigent/extraction/baseline.py` | **Project 1a's classical baseline** (2026-09-30): TF-IDF over word 1–2-grams into `LogisticRegressionCV`, predicting `direction` alone, graded by `run_eval` + `field_match(("direction",))` so its report sits beside the LLMs'. Three arms: `majority` (the commonest label among the *other* cases, the floor), `synthetic` (fitted once on `synthetic_training()`, the fine-tune's own 180-row train split, so the two are taught the same headlines), and `leave_one_out` (each case answered by a fit on the other 49). **C is chosen by cross-validation on each training set alone**, never by the test score: at sklearn's default C=1 the 49-row fits answered "up" to every case. `top_terms` prints the n-grams each label leans on. `Outcome.usage` is None, so the runner bills nothing. Measured 26 / 38 / 30 of 50 (`headlines-20260930-0603.md`). Free and offline, seconds. |

### 2.3 Cost and budget (`pricing`)

The only module that knows a price. Two guards at two scales: `assert_request_within_budget` refuses
one call whose worst case is over the per-request ceiling (`llm` applies it to every call before
sending), `Budget` reacts after the call that crosses a ceiling — the only honest moment, since
what a call cost is not knowable until it is done. **`Budget.admit` closes the gap between them**
(2026-09-21): what a call *could* cost is knowable before sending, so a budget refuses any call whose
worst case would carry it past its ceiling, and the run never crosses it at all.

### 2.4 The model door (`llm`)

The one door to a model, and since 2026-09-23 it holds no wire of its own: `adapters` own the wire
formats, `config` builds the client and `pricing` knows the prices; this is where they meet a
request. Every public method runs the same steps in the same order:
count (free, schema included) → check the per-request ceiling → admit against the budget → send
→ bill and trace. A method that returns a judgement (`text`, `record`) bills *before* it judges,
so a refused or truncated call still shows in the trace and the total.

### 2.10 The first agent (`agent`)

The contrast to §2.9: the model chooses which searches to run and when it has enough. One function,
`run(llm, search, question)`, on `llm.core.run_tools`. It uses the
same `Search` as the patterns, under a run budget (`MAX_USD_PER_RUN`). **Thinking
stays on** (`adaptive`): with it off, Opus 5 can write a tool call as plain text, which ends the loop
looking like an answer. **The conversation is cached** (`cache_control`), because an agent resends
everything before each turn: the first live run's seven turns grew from 1,118 to 29,464 input
tokens and cost $0.626, turn 7 fourteen times turn 1. The catch is the ceiling: a cached turn is
admitted at the cache-write price, so the $0.25 per-request ceiling now binds at about 23,600
input tokens with a 4,096-token output cap, down from about 29,500. **Caching lowers the bill,
not the ceiling.** A run a guard stops returns what it searched instead of raising, so a stopped
run still shows its evidence, and the demo moves on to the next question. **Two follow-ups**
(2026-09-22): turns are held to `MAX_USD_PER_TURN` ($0.60) rather than the per-request ceiling, and
a run out of turns or budget is told to answer from what it has (`FINISH`) rather than stopping
empty-handed. It comes back with no answer only when not even `MIN_TOKENS_FINAL_ANSWER` fits.

`combine`, which is about these variants disagreeing on the label rather than about retrieval.

`tools` does not import `config`, and `config` does not import `tools`. Keep it that way — it is why
`tools` can be lifted into an SDK tool runner or a LangGraph node by copying two files. Those two
files are the exception to "every constant lives in `config`", and the shape of the exception is the
point: the constants did not stay scattered in `tools.py`, they moved into `tools_config.py`. A
config module that travels with the code it configures keeps both properties — one place per
concern, and no dependency on the rest of the package.

The same rule holds one level up: no module under `evals/` imports anything that does work. `extraction.headlines` is the arrow in the permitted direction — a capability importing the
harness to be measured by it, never the harness reaching for a capability. The harness is handed a
`Task` and knows nothing about what is inside it. `evals.grade`
holds `Outcome` and `Score` rather than the runner, so a grader never imports the runner either —
the dependency runs one way and stays acyclic.

## 4. Invariants

The rules the code encodes. Breaking one of these is a regression even when tests stay green.

1. **Every paid call is preceded by a free count and the per-request check** — for a turn of
   `llm.core.run_tools`, the per-turn check — in `llm.core.Llm._admit`,
   because every call goes through `llm` (invariant 8). The free token count is the guard's input,
   so it counts exactly what the call will send — system, tools, thinking and, for a parse call,
   the schema, which is input too. Until 2026-09-21 no structured call counted its schema, so each
   was pre-flighted 337 to 1,148 tokens short of what it sent; bills and dry-run estimates were
   never affected. A model with no price is refused at this check too, since its worst case would
   read as free.
2. **Cost is reported, always.** Every path prints `describe_usage` or an equivalent cost line. This
   is the repo's stated purpose, not decoration.
3. **The assistant turn is echoed back verbatim**, `tool_use` blocks included (`llm/core.py:267`,
   `agent_graph.py:90`).
4. **All tool results for one turn go back in ONE user message** (`llm/core.py:273`, `agent_graph.py:118`).
   Splitting them trains the model out of parallel tool calls. `tests.llm.test_core` and
   `tests.test_agent_graph` assert this explicitly.
5. **Tool errors are `tool_result` with `is_error: True`, never exceptions.** `execute_tool` catches
   everything. The model can recover from a message; it cannot recover from a traceback.
6. **Both loops are capped** (`config.MAX_AGENT_TURNS` = 25) and backed by two dollar ceilings, both
   checked before each call since 2026-09-21. An uncapped loop is a cost bug waiting to happen. The
   ceilings are the policy and the cap the backstop: it is set well past where the budget ends a
   real run, so it binds only on a loop of cheap turns. The
   SDK's tool runner has no cap unless one is passed and ends quietly when it runs out, so
   `llm.core.run_tools` always passes one and raises `TurnsExhausted` at it.
   With `finish`, the last turn under the cap is the answer turn, so the cap still counts every
   call; the answer turn is admitted like any other, at a cap sized to fit.
7. **A file tool resolves before it compares.** `.resolve()` then `is_relative_to` defeats `..`,
   absolute paths, and symlinks alike — all three are tested, for reads and writes. The check lives
   once, in `tools._in_sandbox` (2026-10-08); any new filesystem tool goes through it rather than
   repeating it, and no tool takes a path without it.
8. **`config` holds every tunable constant that is not a client's own, each client's live in
   `llm/adapters/cfg_<name>.py`, and each adapter builds its own vendor client; `pricing` is
   the only module that knows a price; an adapter is the only module that talks to a model, and
   every call reaches one through `llm`.** The third clause is enforced by `tests.llm.test_core`, which
   scans the package and fails on any file but `llm/adapters/anthropic.py` that
   calls `.messages.{create, parse, stream, count_tokens, tool_runner}`; it is what makes invariants 1 and 22 hold everywhere at once.
   **No module outside `llm/adapters/` imports a provider SDK** (2026-09-23), `llm` included: requests
   are built from `messages` types and replies are read off `llm.messages.Reply`, so a caller cannot
   depend on a provider by accident, and a second wire is a class in `ADAPTERS` rather than a
   branch through `llm`. Which client an `Llm` talks to is decided once, at construction, by
   name (`config.CLIENT`) — never per call site, and never by naming an adapter class: the wire is
   infrastructure, and a caller only picks the client. New modules import `MODEL` (or `JUDGE_MODEL`, if they grade), they do not name a model,
   and they never do cost arithmetic of their own. Both defaults must appear in `llm.pricing.PRICES`: an
   unknown model costs `0.0` rather than raising, so a typo in a default would report every run as
   free. `tests.llm.test_pricing` pins this. `pricing` imports `config`, never the reverse. The one
   exception to the constants half is the `tools` / `tools_config` pair, which is isolated on purpose
   and carries its own config — see §3.
9. **Paid tests carry `@pytest.mark.live`** and are deselected by default.
10. **Types are complete.** `pyright` runs in standard mode; `cast` is used where SDK stubs are loose
    (`tests/llm/test_core.py:662`), never `# type: ignore`.
11. **An eval survives its own bad rows.** A task that raises, a task that reports an error, a grader
    that raises — each becomes one row in the report, and the run continues. The dataset is validated
    in full *before* the first paid call, so the failures that do happen are the system's, not the
    labels'.
12. **Every dollar an eval spends lands in one budget.** The task reports usage in `Outcome`, a paid
    grader in `Score`, and `run_eval` bills both to one `Budget` via `charge`. Pricing stays in
    `pricing`: nothing under `evals/` calls `usage_cost` itself. A grader that spends silently would
    make the printed total a lie. Rows run concurrently only under a whole-run `worst_usd`, and the
    `Budget` they share is locked (2026-10-07).
13. **A model is asked to read, never to join.** `extraction` has the model copy the company as the
    headline writes it, and resolves the NSE ticker in code from `evals/reference/nse-tickers.json`
    (`headlines.py:137`). A dictionary lookup is exact, free and cannot invent a plausible-looking
    wrong symbol; a miss is `None` plus a line in `report_unresolved`'s to-do list, which is a gap in
    the reference data rather than a silently wrong row. Reach for this wherever a deterministic
    mapping exists — ticker lookup in Week 1, and in Week 2 `Inventory.containing`, which resolves a
    labelled quote to the chunk ids that hold it instead of labelling ids by hand. **The one exception, and it is a
    knowledge question rather than a join:** an unlisted subsidiary has no directory entry and no
    enumerable set, so the `company` description asks the model to name the listed parent instead
    (`Reliance Jio` → `Reliance Industries`). The model supplies the fact; code still does the
    lookup.

14. **The harness imports no capability module.** `evals/` depends on `config` and on itself. It is
    handed a `Task` and knows nothing about what is inside it — which is the only reason Week 2 can
    point it at a retrieval function that never calls the API.

15. **An eval is a measurement, so nothing about it may wobble.** Extended thinking is off for eval
    runs (`config.THINKING_EVAL`), because an instrument that answers differently on consecutive
    identical runs cannot rank two prompts — and it did: one row of `headlines.jsonl` was right on
    one run and wrong on the next with nothing changed but the day, which was reported as a
    standing disagreement with the model before the cause was found. `temperature` and `top_p` are
    **deprecated across Claude 5**, so thinking is the only control left; check this first when a
    future model removes it too. The same rule is why the judge is a different model from the one
    under test, and why graders are pure functions wherever the grading admits one.

16. **A prompt never quotes its own test set.** An illustration in a field description or a worked
    example that is also a dataset row hands the model that row's answer, and the row stops
    measuring anything while still counting as a pass. `tests.extraction.test_headlines` enforces it on
    four-word runs; writing the spec is exactly when this happens, because the clearest example of
    a rule is usually the case that forced you to write it. Pick a company and a metric the dataset
    does not use. **The same holds for training data** (2026-09-28): `extraction.synthetic` drops
    any template headline sharing a four-word run (`headlines.word_runs`) with a real one — 38 of
    2,000 candidates did — and `tests.extraction.test_synthetic` checks the set it writes.

17. **A chunk id belongs to one inventory, and the inventory names its strategy.** Ids are
    positional (`RELIANCE-FY25#0042`), so they survive a re-embed and deliberately do *not* survive
    a re-chunk: the 43rd chunk of a differently-split document is different text, and pretending
    otherwise would silently rewrite every label that named it. This is why a retrieval label is a
    **quote** rather than an id — `Inventory.containing` resolves it against *this* inventory, so
    one labelled dataset can score four chunking strategies. Quote a number with the strategy that
    produced it or do not quote it.

18. **Retrieval is graded before generation, and it is free.** `retrieval` calls no API, so a recall or
    MRR number can be re-measured as often as the question is worth asking. Keep it that way: a
    generator cannot cite what retrieval never handed it, so a wrong answer on a case that scored
    zero on recall is not the generator's bug, and a pipeline measured only end to end cannot say
    which half to fix.

19. **A page never leaves the page sequence.** Ingestion drops text — furniture, blank covers,
    pages that were only an image — but never a *page*. `strip_furniture` empties a page rather
    than removing it, and `page_starts` keeps an entry for it, because the page index is what a
    citation resolves through: drop page 40 and every citation from there on is one page early,
    in a document nobody will check by hand. The same rule is why `page_starts` is built while
    joining the *normalised* pages. A wrong page number is worse than no page number — it is a
    citation that looks checkable and is not.

20. **A retrieval label must identify one document, not merely appear in one.** A quote is the
    label (invariant 17), and a quote that is true of two companies resolves to chunks in both —
    so the retriever is scored wrong for returning a chunk that genuinely holds it. `verify`
    checks the corpus, not just the home document. The three checks that came first all asked
    whether the quote was *in* the document; none asked whether it was *of* it, and boilerplate —
    an auditor's name, a standard BRSR row, a SEBI regulation — is exactly the text that is in
    every report and of none of them.


21. **The ranking that is measured is the ranking that is used.** `retrieval.rank` owns the six
    methods; `evaluate` scores the rankers `build_ranker` makes, and anything that searches the
    reports asks `build_ranker` for one too. Both restructurings — the move out of `evaluate`, then
    the split into ranker classes — were checked by rerunning the free six-arm eval: identical on
    all 324 rows, failures included, each time. A caller that composed its own retrieval would be
    running a retriever no number in this repo describes.

22. **A ceiling refuses spending before it happens, not only after.** Every budget in the repo admits
    the worst case of what it is about to spend: every call through `llm`, which admits it
    against its `Llm`'s budget, and an eval as a whole run through `run_eval(worst_usd=...)`, the
    question generator as a whole before its first call. `Budget.add` and the eval's per-row trip
    remain, as backstops for an estimate that runs low. The trade is deliberate and has a price:
    a worst case assumes the full output cap, so a run stops while it still has some budget left,
    rather than finishing one call over. A new paid path that takes a budget and does not admit
    against it has only half a ceiling. **A call that may write the cache is admitted at the
    cache-write price for all of its input** (2026-09-22): a miss writes the whole prefix, so a
    worst case priced at the read rate would be a guess. Caching lowers the bill, never the
    ceiling — which is why the agent's per-request ceiling binds earlier once it caches. The 1-hour
    cache is admitted at its own 2× write price (2026-10-07; refused until pricing modelled it).
    **Calls in flight count** (2026-09-22): every call `llm` admits is held until it is billed, so
    parallel callers — a framework's nodes, threads — are admitted against what is already running,
    not only what is spent. **Web search is the one estimate** (2026-09-22): its fee is exact at its cap, but its results
    arrive mid-call as input no count can see, so they are priced at `WEB_SEARCH_RESULT_TOKENS`
    each. A search with no cap, and any server tool pricing does not model, is refused.
23. **Every error the package defines lives in `errors`.** Reuse one before adding another, and put
    a new one there rather than beside the code that raises it. `errors` imports nothing, so a
    module never needs another to raise. `llm.core.Rehearsed` is the one exception class outside it: a
    dry-run signal carrying a `Request`, not an error. Nothing checks this yet; it is a convention.
24. **A call is shaped by the client it goes to.** Its model and its output cap are that client's
    own, resolved where the call is built — `spec(client).model`, `max_tokens(site, spec(client))`
    — and never read from an import-time constant, which names the *configured* client and is wrong
    the moment a run names another. Both halves were found late: the model by a live call on
    2026-09-23, when a local server was asked for `claude-opus-5`, and the cap on 2026-09-28, when
    the 09-24 scratch runs turned out to have answered under Anthropic's cap rather than their own.
    `tests.retrieval.test_answer` and `tests.evals.test_graders` each hold one call site to it.
25. **A cache is keyed by everything that made its contents, and is asked for, never assumed.**
    The PDF text cache hashes the file's bytes and the ingestion code; the index cache hashes the
    embedder, its `embed_documents` source and every chunk's id and text. Neither has a version
    number to remember to bump, both rebuild a damaged entry rather than raising, and both are off
    unless a caller passes `--cache`, because a stale hit is wrong quietly. A key that leaves out
    an input is a cache that serves the old answer to a new question: the scratch index cache was
    keyed on chunk ids, which are positional, so it would have survived any edit that kept them.
26. **Tracing observes and never steers** (2026-10-06). An observation never changes what is
    sent, what a tool returns or what a row scores; an exception inside one is marked and re-raised,
    not swallowed. Without both Langfuse keys nothing is traced, and every test traces into
    conftest's `Recorder` (autouse), so no test can reach Langfuse even with keys in `.env`.
27. **A request is sent again only if it cannot have been billed** (2026-10-06): a refusal status
    or a connection that never reached the server, through `llm.adapters.retry`, the only retry layer.
    A timeout or a dropped response raises instead, since a second send could be a second charge
    that no budget saw.
28. **Text someone else wrote reaches the model fenced** (2026-10-06). A tool whose output a third
    party authored (`tools.UNTRUSTED_TOOLS`) has it wrapped by `tools.execute_tool` in an
    `<untrusted>` element it cannot close, so every caller of the dispatcher sees it fenced, and the system prompt says fenced text is data. A new tool that
    returns files, pages or messages joins `tools.UNTRUSTED_TOOLS`; `tools.read_file` itself
    still returns the file as written. A credential never travels: a task
    carrying one is refused, an answer carrying one is withheld, from the judge too, and every
    trace is masked before it leaves the machine.
29. **A write runs only where a caller opted in, and never overwrites** (2026-10-08). The agents
    dispatch whatever tool name the model sends, so `tools.execute_tool` refuses a `WRITE_TOOLS`
    name unless `writes=True`, which only `mcp_server` passes; `write_file` opens with mode `"x"`,
    so the tracked fixtures in `sandbox/` cannot be changed by any tool.
